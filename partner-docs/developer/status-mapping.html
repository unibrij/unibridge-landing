Status Mapping

Common UniBridge settlement statuses during controlled pilot testing. Status values may vary by corridor, provider, and approved integration scope.

Lifecycle overview

created
→ waiting_ramp_payment
→ funding_confirmed
→ submitted / executing
→ processing
→ completed

Failure, retry, or manual review states may occur at different points in the lifecycle.

Core statuses

StatusMeaning
createdSettlement record has been created.
waiting_ramp_paymentSettlement is waiting for provider-handled payment or funding completion.
funding_confirmedFunding has been observed and confirmed; execution has not yet completed.
submittedExecution has been submitted or queued for provider execution flow.
executingExecution has been claimed and is in progress.
processingExecution provider processing or provider status reconciliation is in progress.
completedFinal success confirmed through provider status reconciliation.
failedFinal failure state.
execution_retryableExecution failed before a dangerous provider-side finality point and may be retried.
manual_resume_requiredOperator/manual reconciliation is required before continuing or closing.

Execution readiness

After funding confirmation, UniBridge may check whether the settlement is executable.

  • Funding amount
  • Funding asset
  • Funding network
  • Token contract address where applicable
  • Destination payout details
  • Selected route compatibility
  • Duplicate or already-submitted execution checks

Completion

completed should only be treated as final when:

  1. Funding has been observed or confirmed.
  2. Execution has been submitted.
  3. An execution provider reference has been recorded where applicable.
  4. Provider status reconciliation confirms a successful outcome.

Provider status normalization

Provider-side signalNormalized interpretation
donesuccess
successsuccess
complete / completedsuccess
pendingpending
processingpending
failed / error / rejectedfailed
refundedrefunded
Unknown or missing statusunknown

Manual review

  • Funding evidence is incomplete
  • Funding is confirmed but execution readiness checks fail
  • Provider status is unclear
  • Amount or asset mismatch is detected
  • Provider response is delayed or inconsistent
  • A provider terminal status requires reconciliation
  • Retry would be unsafe without operator review
Partners should not rely on an intermediate status as final settlement completion.
