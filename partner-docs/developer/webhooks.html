Webhook Events

This document describes webhook behavior for controlled UniBridge integration review.

Current implementation note

The current codebase includes provider webhook receivers for funding and execution providers. These are provider-facing webhook receivers and are not the same as a stable partner-facing webhook delivery contract. 

/v2/webhooks/transak
/v2/webhooks/onramp
/v2/webhooks/smartpay
/v2/webhooks/guardarian

Partner webhook availability

Partner-facing webhook delivery may be made available only under an approved private integration scope. Unless partner webhooks are explicitly enabled, partners should rely on: 

GET /v2/settlement/status?settlement_id=<settlement_id>

Conditional partner webhook model

If partner webhook delivery is enabled, UniBridge may send lifecycle events covering both funding and post-funding execution.

Example funding event

{
  "event": "settlement.funding_confirmed",
  "data": {
    "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
    "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
    "status": "funding_confirmed",
    "funding": {
      "asset": "USDT",
      "network": "polygon",
      "observed_amount": 10,
      "observed_tx_hash": "0x..."
    }
  },
  "created_at": "2026-01-01T12:03:00Z"
}

Example execution event

{
  "event": "settlement.execution_submitted",
  "data": {
    "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
    "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
    "status": "processing",
    "execution_provider": "smartpay",
    "provider_ref": "execution-provider-reference-if-available"
  },
  "created_at": "2026-01-01T12:04:00Z"
}

Example final event

{
  "event": "settlement.completed",
  "data": {
    "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
    "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
    "status": "completed",
    "provider_status": "done",
    "provider_ref": "execution-provider-reference-if-available"
  },
  "created_at": "2026-01-01T12:05:00Z"
}

Completion guidance

Partners should not treat settlement.funding_confirmed as final payout completion. Final completion requires a final status such as settlement.completed, or equivalent status confirmation through the settlement status endpoint.

Recommended default

Until partner webhook delivery is explicitly enabled, partners should use status polling through GET /v2/settlement/status.
