Settlement API

The Settlement API creates a controlled payout execution record from a selected quoted route.

Current settlement flow

POST /v2/settlement/create
POST /v2/funding/session
POST /v2/settlement/confirm
GET  /v2/settlement/status

Settlement lifecycle

settlement created
→ funding session created
→ provider checkout / funding instructions returned
→ funding observed / confirmed
→ settlement confirmation dispatched
→ execution readiness checked
→ execution submitted to configured execution provider
→ execution provider reference recorded
→ provider status reconciled
→ final settlement status updated

1. Create settlement

POST /v2/settlement/create

Creates a settlement from a quoted route, destination payout details, and optional redirect URL. Settlement creation also creates the corresponding funding session and stores the execution route context. 

{
  "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
  "route_id": "route_123",
  "redirect_url": "https://www.unibrij.io/surface",
  "destination": {
    "type": "pix",
    "pix_key": "recipient@example.com"
  }
}
{
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "funding_session_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "status": "waiting_ramp_payment",
  "funding_method": "sender",
  "sender_id": "onramp"
}

2. Retrieve funding session

POST /v2/funding/session

Returns the funding session created for the settlement. Depending on the selected sender, this may return a provider widget URL or direct funding instructions.

}

  "status": "created",
  "sender_id": "onramp",

  "funding": {

    "network": "polygon",

3. Confirm settlement

POST /v2/settlement/confirm

Dispatches the next step after provider-handled funding has been confirmed. This endpoint does not confirm funding by itself. 

{
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000"
}
{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "action": "execution",
  "status": "submitted",
  "idempotent": false,
  "funding_transform_status": null
}
Settlement confirmation is a dispatch step, not final payout completion.

4. Post-funding execution

After funding is observed or confirmed and settlement confirmation is dispatched, UniBridge may perform execution readiness checks, submit execution to the configured provider, record a provider reference, reconcile provider status, and update the final settlement status.

5. Check settlement status

GET /v2/settlement/status
curl "https://api.example.com/v2/settlement/status?settlement_id=sett_123e4567-e89b-12d3-a456-426614174000"
{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
  "status": "completed",
  "provider_status": "done",
  "last_polled_at": "2026-01-01T12:05:00Z",
  "updated_at": "2026-01-01T12:05:10Z"
}

Completion rule

A settlement should not be treated as completed based on funding confirmation or settlement confirmation alone. Final completion requires execution submission, an execution provider reference where applicable, and successful provider status reconciliation.
