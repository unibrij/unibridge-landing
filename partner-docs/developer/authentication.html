API Authentication

UniBridge partner-facing /v2 API requests are protected by partner HMAC authentication.

Required headers

Partner POST requests must include:

Content-Type: application/json
x-ub-partner-id: <partner_id>
x-ub-signature: <hex_hmac_signature>

Signature model

The HMAC signature is computed over the exact raw JSON request body sent to UniBridge. The server verifies the signature using the partner secret configured for the provided x-ub-partner-id.

Node.js signing example

import crypto from "crypto";

function signPayload(body, secret) {
  const rawBody = JSON.stringify(body);

  const signature = crypto
    .createHmac("sha256", secret)
    .update(rawBody)
    .digest("hex");

  return {
    rawBody,
    signature
  };
}

const body = {
  session_id: "sess_example",
  amount: 10
};

const { rawBody, signature } = signPayload(
  body,
  process.env.UNIBRIDGE_PARTNER_SECRET
);

console.log(rawBody);
console.log(signature);

cURL example

curl -X POST "https://api.example.com/v2/session/quote" \\
  -H "Content-Type: application/json" \\
  -H "x-ub-partner-id: partner_demo" \\
  -H "x-ub-signature: <computed_hmac_signature>" \\
  --data '{"session_id":"sess_example","amount":10}'

Important signing rule

The signature must match the exact JSON body bytes. If a client signs compact JSON but sends pretty-printed JSON, signature verification may fail because the raw body is different.

Credential handling

  • Do not expose API secrets in frontend code.
  • Do not commit secrets to source control.
  • Do not share credentials outside the approved integration team.
  • Do not reuse production credentials in test environments.
  • Do not reuse test credentials in production environments.

GET requests

In the current implementation, GET requests are not passed through partner HMAC verification. Partners should still treat status endpoints and returned settlement data as private integration data.

Post-funding execution access

HMAC authentication protects partner-initiated API calls. Post-funding execution steps may be triggered by provider-side funding confirmation, internal reconciliation, or approved operational workflows. Partners should track the resulting settlement state through the status endpoint or partner webhooks where explicitly enabled.

Access limitation

Authentication credentials do not create production approval or unrestricted access. All access remains subject to corridor scope, partner review, operational readiness, and written approval from UniBridge.
