Developer Integration

Developer Overview

Private developer-facing documentation for selected partners reviewing a controlled UniBridge integration.

The current integration model is based on the /v2 API surface. UniBridge provides a non-custodial execution coordination layer for controlled payout testing.

Integration model

The partner integration flow allows an approved partner system to:

  1. Register a session.
  2. Resolve the available funding sender and execution options.
  3. Request a quote.
  4. Create a settlement using a selected route and destination payout details.
  5. Retrieve the funding session and provider checkout or funding instructions.
  6. Wait for provider-handled funding to be observed and confirmed.
  7. Dispatch the funded settlement to the next operational step through settlement confirmation.
  8. Allow UniBridge to perform execution readiness checks after funding confirmation and settlement confirmation dispatch.
  9. Allow UniBridge to submit execution to the configured execution provider.
  10. Track the execution provider reference and provider status reconciliation.
  11. Track settlement status through final outcome.
  12. Review execution evidence and final status.

Core API flow

/v2/session/register
→ /v2/session/resolve
→ /v2/session/quote
→ /v2/settlement/create
→ /v2/funding/session
→ provider-handled funding
→ funding observed / confirmed
→ /v2/settlement/confirm
→ execution readiness check
→ execution submission
→ execution provider reference recorded
→ provider status reconciliation
→ /v2/settlement/status

What UniBridge coordinates

  • Session registration
  • Sender and execution route resolution
  • Quote and route preparation
  • Settlement creation
  • Funding session creation
  • Funding status observation
  • Settlement confirmation dispatch after funding is observed or confirmed
  • Execution readiness checks
  • Execution submission to the configured execution provider
  • Execution provider reference recording
  • Provider status reconciliation
  • Final settlement status tracking
  • Execution evidence generation

What UniBridge does not do

  • Custody customer funds
  • Process card payments
  • Collect card details
  • Hold customer balances
  • Provide public remittance services
  • Replace regulated providers
  • Assume provider-side compliance obligations

Current completion model

A settlement should be treated as completed only when:

  1. Funding has been observed or confirmed.
  2. The funded settlement has been dispatched to the next operational step where required.
  3. Execution has been submitted to the configured execution provider.
  4. An execution provider reference has been recorded where applicable.
  5. Provider status reconciliation confirms a successful outcome.
Funding confirmation alone does not represent final execution completion. Settlement confirmation dispatch alone does not represent final execution completion.

Access model

Developer access is private and controlled. API credentials, endpoint availability, corridor availability, and production use require separate approval from UniBridge.
