API Reference

Confirm Settlement

POST /v2/settlement/confirm

Dispatches the funded settlement into the next operational step after provider-handled funding has been observed or confirmed.

This endpoint does not confirm funding by itself and does not represent final payout completion.

When to call

This endpoint is called after provider-handled funding has been observed or confirmed for the approved partner flow.

Request body

FieldTypeRequiredDescription
settlement_idstringYesSettlement created through /v2/settlement/create.

Example request

{
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000"
}

Example response: execution dispatch

{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "action": "execution",
  "status": "submitted",
  "idempotent": false,
  "funding_transform_status": null
}

Example response: idempotent no-op

{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "action": "noop",
  "status": "submitted",
  "idempotent": true,
  "funding_transform_status": null
}

Possible dispatch actions

ActionMeaning
executionThe settlement was dispatched toward execution handling.
funding_transformThe settlement was dispatched into an intermediate funding transform step where applicable.
noopThe settlement was already dispatched or no further dispatch was required.

Important behavior

  • Settlement confirmation is a dispatch step.
  • It does not mean the final payout has completed.
  • Partners should not retry blindly if the resulting state is unclear.
  • Partners should continue tracking status through GET /v2/settlement/status.

Possible errors

ErrorMeaning
missing_settlement_idsettlement_id was not provided.
settlement_not_foundSettlement does not exist.
funding_not_confirmedFunding has not been observed or confirmed.
invalid_settlement_stateThe settlement is not in a state that can be confirmed or dispatched.
manual_resume_requiredManual review is required before continuing.
