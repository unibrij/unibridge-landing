API Reference

Settlement Status

GET /v2/settlement/status

Returns the current settlement state through the controlled settlement lifecycle.

Query parameters

ParameterTypeRequiredDescription
settlement_idstringYesSettlement identifier returned by /v2/settlement/create.

Example request

curl "https://api.example.com/v2/settlement/status?settlement_id=sett_123e4567-e89b-12d3-a456-426614174000"

Example response: funding confirmed, execution not final

{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
  "status": "funding_confirmed",
  "execution_amount_executable": true,
  "execution_reason": null,
  "provider_status": null,
  "updated_at": "2026-01-01T12:03:00Z"
}

Example response: processing

{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
  "status": "processing",
  "provider_status": "pending",
  "last_polled_at": "2026-01-01T12:04:00Z",

}

Example response: completed

{
  "ok": true,
  "settlement_id": "sett_123e4567-e89b-12d3-a456-426614174000",
  "session_id": "sess_123e4567-e89b-12d3-a456-426614174000",
  "status": "completed",
  "provider_status": "done",
  "last_polled_at": "2026-01-01T12:05:00Z",
  "updated_at": "2026-01-01T12:05:10Z"
}

Completion rule

Funding confirmation alone does not represent final execution completion. Settlement confirmation dispatch alone does not represent final execution completion. Final completion requires execution submission, an execution provider reference where applicable, and successful provider status reconciliation.

Polling guidance

  • Avoid excessive polling.
  • Treat funding_confirmed as non-final.
  • Treat submitted as non-final.
  • Treat processing as non-final.
  • Treat completed as final only when supported by execution evidence.

Possible errors

ErrorMeaning
missing_settlement_idsettlement_id was not provided.
settlement_not_foundSettlement does not exist.
