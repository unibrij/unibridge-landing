UniBridge

How UniBridge Works

UniBridge makes destination payout readiness explicit before funding begins. This page outlines how execution is defined, committed, and enforced across regulated partners without taking custody of funds.

What UniBridge Does

UniBridge is a coordination layer for cross-border payouts.

It enables applications and wallets to determine how a payout will be executed across multiple regulated partners — before any funds move.

UniBridge does not custody funds. It defines and coordinates execution conditions in advance, so payout delivery is not left to post-funding uncertainty.

Execution Lifecycle

Each payout follows a coordinated process in which execution conditions are established before funding begins.

Execution is defined → validated → committed → then triggered upon funding

The exact execution path is resolved prior to fund movement and then enforced during execution across the selected destination rail.

Use Case

A payout application or wallet can use UniBridge to coordinate a destination payout flow:

  • Initiate a payout session
  • Resolve available execution paths for the corridor
  • Commit to a selected route
  • Provide funding only after execution is ready
  • Trigger payout delivery across local rails

Final delivery occurs through local payment networks such as bank transfer, wallet payout, or PIX, depending on corridor and partner configuration.

Control Model

UniBridge coordinates what should happen before funds move, while execution authority remains with the relevant regulated participants.

It does not replace custody, signing, or licensed execution providers. Instead, it makes the committed route explicit, aligns the roles involved, and reduces ambiguity between settlement and payout delivery.

Routing is committed before funding. Custody and execution remain with the appropriate parties.

Architecture

UniBridge separates payout coordination into logical layers:

Client Application → Session → Coordination → Settlement Context → Execution

This structure allows payout readiness, route commitment, and execution logic to be handled in sequence without UniBridge holding funds or directly operating local payout rails.
