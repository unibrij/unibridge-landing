Operating Model

One payment path. Clear roles at every step.

UniBridge coordinates funding, settlement, and local payout across the providers responsible for each step — without taking custody of customer funds.

UniBridge coordinates the path

UniBridge connects funding, settlement, and payout across the providers selected for each route.

Applications and wallets can define the destination, start funding, track status, and follow execution through one coordinated flow.

UniBridge does not hold customer funds, operate local payout rails directly, or replace the providers responsible for regulated activities.

From intent to payout

Each route moves through defined stages before execution.

Defined → Validated → Committed → Triggered upon funding

Each stage makes the route, funding state, execution status, and return handling visible before the next step begins.

How a payment moves

An application, wallet, or platform can use UniBridge to:

  • Create a payment session
  • Find the available route
  • Select how the recipient gets paid
  • Start funding
  • Follow the payment through delivery or return

The same path can end in a bank account, wallet, PIX, or another supported local payment method, depending on the route and provider configuration.

Clear roles. No custody.

UniBridge coordinates the payment without becoming the custodian or the local payout provider.

Funding, compliance checks, custody, and final execution remain with the providers responsible for those functions.

One coordinated route, without local prefunding or dependence on a single provider.

What sits underneath

UniBridge keeps the payment flow separated into clear operating layers.

Client → Session → Coordination → Settlement Context → Execution

Each layer has one job, so route selection, funding, execution, status, and return handling can evolve without collapsing into one provider-specific flow.
