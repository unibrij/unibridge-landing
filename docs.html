UniBridge Documentation

What UniBridge Does

UniBridge is a coordination layer for cross-border payouts.

It enables applications and wallets to determine how a payout will be executed across multiple regulated partners — before any funds move.

UniBridge does not custody funds. Execution conditions are defined and enforced prior to movement.

Architecture

UniBridge separates payout coordination into logical layers:

Client Application → Session → Coordination → Settlement Context → Execution

UniBridge does not hold funds or execute payouts directly. It orchestrates execution across independent partners.

Execution Lifecycle

Each payout follows a coordinated process where execution conditions are established in advance.

Execution is defined → validated → committed → then triggered upon funding

The exact execution path is resolved prior to fund movement and enforced during execution.

Use Case

A remittance application initiates a payout request:

  • Initiate payout session
  • Resolve available execution paths
  • Commit to a selected route
  • Provide funding
  • Trigger execution across local rails

Funds are delivered through local payment networks such as bank transfer or PIX.

Execution Model

UniBridge ensures that execution conditions are established before funding occurs.

This removes uncertainty between settlement and final payout delivery.

Deterministic execution is enforced at the coordination layer.
